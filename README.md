# 失敗写真チェッカー (PhotoCull)

たくさんの写真を読み込んで、失敗写真を自動で見つける Windows アプリです。
インターネット接続は不要で、写真はすべて PC の中だけで処理されます。

## ダウンロード

[Releases](../../releases/latest) から `PhotoCull_v1.0.zip` をダウンロードして展開し、`PhotoCull.exe` を起動します
（インストール不要。Windows 10 / 11 の 64 ビット）。署名のない exe なので、初回起動時に Windows の警告が出ることがあります
（「詳細情報」→「実行」で起動できます）。

ライセンスは AGPL-3.0 です（物体検出に使っている YOLO11 が AGPL-3.0 のため）。

## 使い方

1. `PhotoCull.exe`（自分でビルドした場合は `dist\PhotoCull.exe`）をダブルクリックして起動する（初回起動は 5〜10 秒ほどかかります）
2. 「📁 フォルダを開く」を押すか、写真やフォルダをウィンドウにドラッグ＆ドロップする
3. 解析が終わると、失敗写真には赤枠と理由が表示される。サムネイルの右上の青い印は、判定に使った被写体（人物・サーフボードなど）
   - 上の「表示」で、失敗の理由ごと（ピンボケだけ、手ブレだけ など）に絞り込める。かっこ内は枚数
   - その下の「タグ」で、写っている物（80 種類: 人物・サーフボード・犬・車・鳥・ボート など）で絞り込める
     - 検索欄に文字を入れるとタグを探せる（日本語・英語どちらでも。「さーふ」「サーフ」「surf」のどれでも見つかる）
     - タグをクリックしてチェックを付けると、その物が写っている写真だけを表示する（複数選択可）
     - 「どれかが写っている／すべて写っている／写っていない」を切り替えられる
   - 写真を選ぶと、右のプレビューに被写体の形（緑）、ほかに見つかった物（灰）、顔（黄）が表示される
4. 必要に応じて手動で直す
   - **F** = 失敗にする / **G** = OK にする / **R** = 自動判定に戻す（複数選択可）
   - ダブルクリックで写真を Windows の標準ビューアで開く
5. 「✕ 失敗写真を移動・コピー ▾」または「✓ OK の写真を移動・コピー ▾」から「移動する…」「コピーする…」を選ぶ
   - 行き先は次のどちらかを選べる
     - 元の写真と同じフォルダの中に `_失敗写真` / `_OK写真` フォルダを作って入れる
     - 好きなフォルダを指定する（「参照…」の画面の「新しいフォルダー」で作れる。入力した場所に無ければ自動で作る）
   - 「同じ名前の RAW ファイルも一緒に移動・コピーする」がオン（初期設定）なら、`IMG_0001.JPG` と一緒に
     `IMG_0001.RAW` のような同じ名前の RAW も動かす（.RAF / .NEF / .CR3 / .ARW / .DNG など主な RAW と、編集情報の .xmp に対応）
   - 同じ名前の写真があるときは上書きせず `名前_1.jpg` のように番号を付ける（JPG と RAW は同じ番号にそろえる）
   - 移動した直後なら「↶ 移動を元に戻す」(Ctrl+Z) で元に戻せる（アプリが作ったフォルダは空になれば消える）
6. 「CSV に書き出し」で判定結果と測定値を一覧で保存できる

対応形式: JPG / PNG / BMP / TIFF / WebP（RAW と HEIC には対応していません）

## 処理速度とグラフィックボード（GPU）

物体（タグ）検出の AI はグラフィックボードで動かします（左の「処理速度」→「グラフィックボード（GPU）を使う」、初期設定はオン）。
Windows 標準の DirectML を使うので、NVIDIA / AMD / Intel のどれでも動き、CUDA などの追加インストールは不要です。
画面右下に「AI処理: GPU」または「AI処理: CPU」と表示されます。GPU が使えない PC では自動的に CPU で処理します。

約 2,000 万画素以上の JPEG 写真での計測（RTX 3060・16 コア CPU）:

| 版 | 解析のみ | 画面に表示しながら |
|---|---|---|
| 最初の版（YOLOX・CPU） | 約 3.8 枚/秒 | ― |
| YOLOX・GPU | 8.2 枚/秒 | 7.4 枚/秒 |
| YOLO11-seg・GPU（高速化前） | 9.8 枚/秒 | ― |
| **YOLO11-seg・GPU（現在）** | **21.7 枚/秒** | **17.1 枚/秒** |

高速化の内容:

- JPEG を「1024px 以上になる倍率」で縮小しながら読み込む（1/4 などで読むと、読み込みも縮小も速い）。
  MPO 形式の JPEG（一部のカメラが使う、プレビュー画像入りの形式）で縮小読み込みが効いていなかった不具合も修正
- 2048px の画像は、ピントや目を判定できる大きさの顔があるときだけ読み直す
- 顔検出は 640px で行い、大きな顔だけ周りを切り出して検出し直す（目の位置を正確にするため）
- 手ブレ解析のフーリエ変換を、半分の計算で同じ結果になる方法（実数 FFT）にし、区画をまとめて計算する
- 並列処理を最大 8 枚にする

高速化の前後で、判定はほとんど変わりません（約 2,200 枚で変わったのは境目にあった 1 枚だけでした）。

GPU を使っても判定結果は変わりません。残りの時間は主に JPEG の読み込みと顔検出（CPU で並列処理）です。

解析中の一覧表示は、0.3 秒ごとに新しく終わった写真だけをまとめて追加します（全体の判定し直しは解析の最後に 1 回）。
以前は 1 枚終わるごとに一覧全体を描き直していたため、枚数が多いほど遅くなっていました
（600 枚で 6.1 → 7.4 枚/秒、画面が固まる時間 15.6 秒 → 2.6 秒）。

## 検出する失敗

| 種類 | 判定方法 |
|---|---|
| ピンボケ | 画面を 8×8 に分け、最もくっきりした部分の鮮鋭度で判定する（被写体が写っていない写真） |
| 相対的なボケ | 同時に読み込んだ写真の中央値の半分未満のもの（被写体は同じ種類どうしで比べる） |
| 手ブレ | 画面全体が同じ方向に流れている写真。方向（横・縦・斜め）も表示する |
| 被写体にピントが合っていない | 被写体（人物など）がボケている、背景にピントが合っている、ほかの写真の同じ種類の被写体よりボケている。人物なら顔のピントも見る |
| 目つぶりの可能性（参考） | 正面を向いた大きめの顔で、両目とも見つからない写真 |
| 暗すぎ・明るすぎ | 平均輝度 |
| 白飛び | 被写体が写っていれば被写体の形の部分、いなければ写真の下 6 割で判定（白く飛んだ曇り空だけでは失敗にしない）。写真の 6 割以上が真っ白なら常に失敗 |
| 黒つぶれ | 真っ黒な画素の面積 |
| コントラスト不足 | レンズのくもりや指かぶりなど、全体が眠い写真 |
| 似た写真（オプション） | 連写などで似た写真が続くとき、最もくっきりした 1 枚以外を失敗にする（初期設定はオフ） |
| 読み込みエラー | 壊れたファイル |

### タグと被写体

物体検出 AI（YOLO11-seg）で、写っている物を 80 種類の中から見つけ、形（マスク）まで切り抜きます。
見つかった物がその写真の「タグ」になり、検索や絞り込みに使えます。

ピントは **被写体** で判定します。左の「被写体」→「被写体の種類」で選べます（文字を入れると候補を探せます）。

- **人物**（初期設定）… 人物を被写体にする。判定の調整は主にこの設定で行っています
- **自動（一番大きく写っているもの）** … 写真ごとに、一番大きく写っている物を被写体にする
  （例: 人より大きなボードが写っていればそのボード。料理の写真なら器）
- **そのほか** … サーフボード・犬・車・鳥など、80 種類から選べる

被写体の判定:

- 背景がボケていても、被写体にピントが合っていれば OK
- 被写体がボケている、または背景のほうが被写体よりくっきりしている（ピントが背景に行った）写真は失敗
- 同じ種類で同じくらい大きく写っている物は、まとめて 1 つの被写体として扱う（誰か一人にピントが合っていれば OK）
- 小さく写っている物（面積 1% 未満）は風景の一部として扱い、写真全体のピントで判定します
- ピンボケの判定は被写体の枠（すぐ周りを含む）で、背景との比較は被写体の形で測ります
  （黒いウェットスーツのように模様の少ない被写体は、形の中だけだとピントが合っていても細部が少なく出るため）
- 顔が小さい（解析画像で 100px 未満）ときは顔では判定せず、人物全体のくっきり具合で判定します
- 逆光で暗い顔は細部の量が小さく出るので、「明暗差に対する細かさ」も見て、両方とも低いときだけボケとします

### 手ブレとピンボケの見分け方

写真を小さな区画に分けて周波数を解析し、方向ごとに「細かい模様 ÷ 粗い模様」の比を調べます。

- 手ブレ: ブレた方向だけ細かい模様が消える → その方向だけ比が下がる
- ピンボケ: 全方向で同じように細かい模様が消える → 方向による差が出ない
- 建物の縦線や水平線など、被写体そのものの向き: 細かい模様にも粗い模様にも同じように現れるので打ち消される

カメラの手ブレは画面全体に同じ向きで出るので、画面の 4 分割すべてで同じ向きに出ているかも確かめます。
一部だけ動いている被写体（走っている人など）は手ブレとしては扱いません。

海面のさざ波や水平線は、それ自体が「横に流れた模様」なので手ブレと取り違えやすくなります。そのため、

- 被写体が写っていれば、**被写体の部分にも同じブレが出ているとき**だけ手ブレとします
- 被写体で確かめられない写真（海・空・風景だけ）は、しきい値を 15 上げて厳しめに判定します

## 判定のしきい値について

初期値は、約 2,200 枚の JPEG 写真を 100% 拡大で目視確認しながら調整しました。
軽いボケは見逃すことがあります。もっと厳しくしたい場合は、左パネルの「中央値に対する割合」を 50% → 60% に上げてください
（失敗と判定される枚数が増えます）。判定に使った測定値は、写真を選ぶと右側に表示されるので、それを見ながら調整できます。

左側のパネルで判定基準を変えると、再解析せずにすぐ判定し直します。
写真を選ぶと右側に測定値としきい値が表示されるので、それを見ながら調整してください。
設定は次回起動時も引き継がれます。

## 不具合が起きたとき

予期しないエラーは次のファイルに記録されます。不具合の報告時に添えてください。

- `%LOCALAPPDATA%\PhotoCull\error.log` … アプリ内で起きたエラー
- `%LOCALAPPDATA%\PhotoCull\crash.log` … アプリが強制終了したときの記録

GPU が使えているかなどは、コマンドプロンプトで次を実行すると `診断.txt` に書き出されます（写真の指定は省略可）。

```
PhotoCull.exe --diagnose 診断.txt C:\写真\IMG_0001.jpg
```

## 自分でビルドする場合

Python 3.10 以上が入った PC で、次の順に実行します。

1. `tools\export_yolo11.py` で物体検出モデル（`photocull\models\yolo11s-seg.onnx`）を作る（最初の 1 回だけ。手順はファイルの先頭に記載）
2. `build.bat` を実行すると `dist\PhotoCull.exe` が作られる
3. 人に渡す場合は `tools\make_dist.py` を実行すると、`release\PhotoCull_v1.0\`（exe・使い方・ライセンス・ソースコード）と
   その ZIP が作られる

このアプリは、YOLO11（AGPL-3.0）を使っているため AGPL-3.0 で配布します（`LICENSE`）。
人に渡すときはソースコードも一緒に渡す必要があるので、`make_dist.py` で作った ZIP をそのまま渡してください。

開発中にソースから直接起動する場合:

```
%LOCALAPPDATA%\PhotoCull\venv\Scripts\python.exe main.py
```

## ファイル構成

- `photocull/analyzer.py` … 画像解析と判定ロジック（OpenCV）
- `photocull/people.py` … 物体（タグ）・顔の検出（物体検出は ONNX Runtime + DirectML で GPU 処理）
- `photocull/models/` … 検出用 AI モデル
  - `yolo11s-seg.onnx` … 物体検出・切り抜き YOLO11s-seg（Ultralytics 社、**AGPL-3.0 ライセンス**）。
    自分で使うぶんには問題ありませんが、この exe を他の人に配る場合は、ソースコードを公開するか
    Ultralytics 社の商用ライセンスが必要です
  - `face_detection_yunet_2023mar.onnx` … 顔検出 YuNet（MIT ライセンス）
- `photocull/app.py` … 画面（PySide6 / Qt）
- `main.py` … 起動用
- `build.bat` … exe 作成スクリプト（PyInstaller）
